# 当前规划骨干（周会汇报版）

## 1. 项目定位

把**无本体 EEF 轨迹数据集**批量重定向到**指定机器人**，输出可用于训练的目标机器人关节轨迹数据集，并附带逐帧诊断、质量报告和完整处理记录。

- 转换机制：IK 求解 + FK 复算验证
- 核心价值：补全并确认坐标系、单位、四元数、TCP、夹爪等缺失语义
- 产品形态：批量处理流水线，三维回放用于抽检和问题定位
- AI 重点：辅助生成新数据格式的 `MappingSpec` 和新机器人配置，不能确定的语义交给人确认

## 2. 核心处理链路

### 2.1 数据结构探测

工具首先只读扫描输入数据集，识别文件组织、episode 与帧的划分、字段路径、shape、数据类型和数值分布。这里不直接猜测字段语义，只生成一份可供后续分析的结构清单。

### 2.2 语义映射与确认

根据结构清单生成 `MappingSpec`，明确哪些字段对应时间、位置、姿态、夹爪、左右臂和辅助通道，同时记录单位、四元数顺序、绝对或增量轨迹、参考坐标系和 TCP 定义。AI 可以生成草稿并附带证据与置信度；无法从数据中确定的坐标系、TCP 等信息必须由人确认。

### 2.3 统一内部表示

不同来源的数据经映射后转换为 `CanonicalTrajectory`。它统一描述时间轴、一个或多个运动组的 EEF 位姿、夹爪状态和同步辅助数据，使后续求解、诊断和导出不再依赖原始数据格式。

### 2.4 目标机器人建模

通过 `RobotProfile` 描述目标机器人的 URDF、受控关节、左右臂等运动组、末端 link、TCP、关节顺序、锁定关节和运动限制。该层负责把通用 EEF 轨迹与具体机器人本体连接起来。

### 2.5 连续 IK 求解

按照时间顺序把 EEF 轨迹转换为目标机器人的关节轨迹。每一帧以上一帧结果作为初值，并考虑关节限位和连续性，避免逐帧独立求解造成 IK 分支跳变。双臂数据按多个运动组联合组织和处理。

### 2.6 FK 复算与诊断

将求得的关节轨迹重新做 FK，与输入 EEF 目标逐帧比较，同时检查位置与姿态误差、不可达区间、关节越界、速度异常、分支跳变、奇异性和碰撞风险。首版负责发现和定位问题，不自动修改数据。

### 2.7 批量报告与数据集导出

对每个 episode 给出通过、警告或失败结论，以及可达率、最大误差、失败区间和主要原因；再汇总整个数据集的质量分布。通过的数据被写回目标机器人关节值，图像、任务、时间戳等通道保持不变，并附加机器人版本、求解配置和误差摘要等谱系信息。

## 3. 技术骨架

### 3.1 数据接入层

- `Prober`：面向 Parquet、HDF5、Zarr、CSV 等容器，负责读取结构与统计信息，不绑定具体 schema。
- `MappingSpec`：版本化 YAML，负责声明原始字段到统一轨迹字段的映射及其语义，是 AI 生成、人工确认和复用的核心契约。
- `DataAdapter`：把已经验证的数据集格式固化为可直接使用的适配器；首个目标是 LeRobot v3.0 双臂数据。

### 3.2 机器人资产层

以 URDF 和 mesh 为唯一主资产，`RobotProfile` 在其上补充运动组、末端与 TCP、关节顺序、锁定关节、位置与速度限制以及能力声明。CuRobo 碰撞球、MJCF 等后端专用文件作为派生配置保存，并记录来源 URDF 的版本和哈希，避免模型与配置不一致。

### 3.3 运动学后端层

- `Pinocchio`：负责 FK、Jacobian、合成测试数据和跨后端结果校验，是始终可用的基础设施。
- `Pink`：首个 CPU IK 后端，用于在普通笔记本上打通完整闭环并建立可信基线。
- `CuRobo`：后续 GPU 后端，用于全量数据集的批量求解、碰撞约束和吞吐加速。

接入顺序为 `Pinocchio → Pink → CuRobo`。先得到可解释、可交叉验证的 CPU 结果，再扩展 GPU，便于区分数据语义、机器人配置和求解器本身的问题。

### 3.4 诊断与质量层

统一计算 EEF 位置和姿态误差、关节限位余量、相邻帧连续性、速度与加速度异常、奇异性及碰撞距离。诊断结果既保存为逐帧指标，也聚合为 episode 和数据集级报告，为筛选训练数据提供依据。

### 3.5 运行与追溯层

原始数据保持只读，每次执行创建独立 run 目录，保存输入哈希、机器人版本、后端与参数、随机种子、求解结果、逐帧指标、质量报告和导出数据。同一份 `recipe` 可以复现实验结果。

### 3.6 可视化与人工介入层

采用薄 React + R3F 页面展示目标机器人、目标 EEF 与 FK 实际轨迹，并把三维回放、时间轴、误差曲线和问题区间关联起来。用户可以跳转到失败片段，调整少量参数并局部重算；可视化服务于抽检和调试，不承担批量主流程。

## 4. 首版范围与里程碑

### M0：合成闭环

完成 Panda、Pinocchio、Pink、统一轨迹结构、CLI 和合成往返测试，验证 `EEF → q → FK → EEF` 闭环。

### M1：真实数据闭环

接入 LeRobot v3.0 双臂数据，支持 MappingSpec、OpenArm、多运动组、批量求解、质量报告和原格式数据集导出。

### M2：可视化闭环

完成三维回放、误差曲线、失败片段定位、参数调整和局部重算。

**阶段性交付目标：** 能处理真实数据、看见回放、定位问题、导出训练数据集，并附质量报告。

后续再做 CuRobo 全量加速、自动修复、更多机器人、仿真接入和开源发布能力。

## 5. 当前待核实项

- OpenArm URDF、mesh、关节限制和命名的完整性
- CuRobo 对双臂、多末端的实际支持程度及现成机器人配置
- MuJoCo Menagerie 的目标机器人覆盖情况
- 可用于单臂真实往返测试的开源数据集及其 EEF 字段
- M1 实测后冻结最终误差阈值

## 6. 一句话总结

当前规划是建设一套面向训练数据的批量本体化流水线：先用 Panda 完成可靠的运动学闭环，再用 OpenArm 和真实双臂数据完成首个正式交付，首版重点保证语义正确、结果可诊断、过程可追溯。
