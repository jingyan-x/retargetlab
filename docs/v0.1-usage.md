# v0.1 使用与输入约定

首版提供配置驱动 CLI、质量报告、浏览器回放和带掩码的 LeRobot 数据导出。Linux x86_64 / Python 3.12 是本轮安装验收范围。先按根 README 跑完公开模型与合成数据示例，再接入已有支持格式。Windows 用户可连接 Linux 服务；Windows 原生安装与 WSL 独立安装尚未验收。

## 两个环境

处理环境安装 wheel 的 `[pipeline]` extra，并用 `retargetlab doctor --scope pipeline --json` 自检。该环境包含 Pink/Pinocchio、Mink/MuJoCo、数据、视频和模型转换依赖，不需要 PyTorch 或 GPU。

读取环境先按 README 安装 CPU PyTorch，再安装同一 wheel 的 `[lerobot]` extra；用 `retargetlab doctor --scope reader --json` 自检。`env/v0.1-process-linux-py312.txt` 和 `env/v0.1-reader-linux-py312.txt` 是各自验收时的依赖约束，可给 pip 加 `-c` 使用。不要混用两个约束文件。默认 `doctor` 保持既有求解环境检查；`--scope core` 仅检查基础包。

LeRobot 读取使用 PyAV 解码视频，不需要 torchcodec。处理与读取分环境是已验证的安装路线，两者通过输出目录交换数据。

## 接入 OpenArm sidecar

`process` 配置中使用 `source_format: openarm_eef_sidecar`，填写 `dataset`、`robot_asset`、明确的 `episode_indices` 和 `backend`。配置中的相对路径相对于配置文件所在目录解析。生成示例中的 `process-pink.json`、`process-mink.json` 是可直接修改的模板。

sidecar 包含 `manifest.json`、`data/eef.parquet`、`assets/source_openarm.urdf`。每行必须包含：

| 字段 | 约定 |
|---|---|
| `episode_index` / `frame_index` | 每个 Episode 内帧号连续 |
| `timestamp` | 秒，有限且严格递增 |
| `observation.eef` / `action.eef` | 两条流各自的16维 EEF；不自动移动 action 时间标签 |
| 单臂8维布局 | `x_m, y_m, z_m, qw, qx, qy, qz, gripper_raw`；先左后右 |
| 位姿 | URDF world 到 hand_tcp 的正向变换，位置单位米，四元数 wxyz |

manifest 必须声明 TCP、坐标语义和指纹。示例由 `demo-init` 生成完整清单；源与目标 URDF 必须匹配。夹爪 raw 只保留原值，模型中每根夹指固定为0.022 m，不表示真实开度映射已经标定。

`training-export` 还需 manifest 所绑定的原 Joint 数据及 LeRobot 元数据，用于求解结束后的独立对照、视频与任务信息保留。`process` 本身只读取 EEF、时间和索引列，源 Joint 不提供求解种子。

## 接入已登记的 MQ03 EEF 布局

使用 `source_format: mq03_eef`、`dataset`、带碰撞资产的 `robot_profile` 和 `split`。目标为既定的 `moqi_mq03_fixed_body`、根 `base_link`、14个受控臂关节。首版不把它当成任意14关节机器人入口。

单臂布局为 `gripper_raw, qw, qx, qy, qz, x_m, y_m, z_m`，先左后右。输入 `meta/info.json` 的 feature names 必须匹配已登记名称；原关节对照在 `.position` 通道中。split YAML 使用 `calibration.episode_index` 和 `held_out.episode_index`；当前入口只处理 calibration，拒绝 held-out 选择。

此路线已在私有登记样本验证，私有数据与 MQ03 资产不随首版示例分发。公开快速开始使用 OpenArm 公共模型。

## 输出和质量

`process --output` 必须指向新目录。`COMPLETED` 表示处理完成，不表示所有帧通过；逐帧检查结果在 `trajectories.parquet`，汇总在 `report.json`、`report.md`。

`training-export` 在实际导出精度下重新核对 FK、限位、速度与策略，保留全部原行，并给出双流联合 `valid.retarget`。示例策略拒绝所有未通过的运动学帧和活动碰撞对。质量策略文件写入产物，不能通过改报告标题把另一种策略当成等价结果。

消费数据使用：

```python
from pathlib import Path
from torch.utils.data import DataLoader
from retargetlab.run.training_dataset import MaskedLeRobotDataset

dataset = MaskedLeRobotDataset(Path("demo/dataset"), action_horizon=16)
batch = next(iter(DataLoader(dataset, batch_size=2, num_workers=0)))
print(batch["observation.state"].shape)  # [2, 16]
print(batch["action"].shape)             # [2, 16, 16]
```

窗口内任一行被剔除、遇到帧号间断或 Episode 边界时，不提供该窗口。原始错误行仍可用于回放定位。`verify-reader` 验证实际读取和归一化，并不训练策略。

## 可选的原生间距导出门槛

MQ03修正版等已绑定MuJoCo模型的处理结果，可在质量策略中显式增加 `native_clearance` 对象，指定 `minimum_distance_m`、`numeric_epsilon_m`、`distance_clip_m` 和 `model_manifest_sha256`。模型指纹必须同时匹配处理输入绑定和实际模型；没有绑定模型的处理结果会拒绝该选项。

导出器会在最终float32手臂关节值上重新计算原生间距。只有位姿、限位、速度、既有碰撞策略和间距均通过的双流时刻才能进入 `valid.retarget`；质量Parquet保留具体间距及判定。未配置该对象时沿用原策略。该门槛描述所绑定的几何模型，不构成真实机械接触或扫掠体积认证。

## 回放

`replay-build --config` 接受条目列表，每项为 `id`、`processing_run`、`model`，以及可选 `quality_dataset`、`label`。相对路径以该配置文件所在目录为基准。构建时验证输入指纹和保存 q 的 FK；回放时不再次求 IK。

交互页面使用本地 WebGL2，不依赖外部 CDN，也无需远端 OpenGL 离屏渲染。旧 `/api/frame` 原生图片接口仍需另行配置渲染环境，首版 quickstart 不使用它。回放 bundle 引用原模型目录，移动处理/模型目录后应重新构建配置与 bundle，不要手改指纹文件。

## 排错

| 现象 | 处理 |
|---|---|
| `ENVIRONMENT_ERROR` | 在对应环境运行带 `--scope` 的 doctor，核对安装 extra |
| 输出目录已存在 | 使用新的 run 名称；不覆盖旧证据 |
| 来源/模型指纹不匹配 | 核对输入版本，按新来源重建处理；不要删除检查 |
| 无完整动作窗口 | 查看质量报告、Episode 长度和 horizon；不应直接忽略掩码 |
| 远端回放打不开 | 确认服务仍运行，SSH 本地端口映射到远端所选端口 |

通用退出码：0为命令成功；2为命令参数错误；3为输入/语义错误；4为既有质量门槛错误；5为依赖环境错误；1为其他运行/验收错误。成功输出中的具体质量状态仍需检查。

## 示例与能力边界

示例的192个时刻、三路 RGB 图案和目标由代码生成，不是现实任务采集。第二个 Episode 在帧48和64附近有故意设置的目标突变，用来演示限速下的失败与窗口过滤。它证明工具链可以复现，不证明实际接触任务成功。

公开 OpenArm 来源为 [enactic/openarm_description](https://github.com/enactic/openarm_description/tree/6148297241fb0402eafe2c6eed455ae4e90d4552)，保留 Apache-2.0 许可证。示例相邻链接 SRDF 根据 URDF 拓扑生成，范围为14个受控关节和两个手部固定连接，不通过统计报警频率删除配对。

几何物理认证、动态夹爪、独立性能评估、全量处理、跨本体重定向、动力学、训练和真机执行属于后续工作，不是这一软件候选的验收声明。
